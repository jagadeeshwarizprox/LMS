# Version 2, 8 October 2026: the wiring pass

Everything on this list was either on screen and failing, or built on the server and
never reachable from a screen. Nothing new was invented beyond what the server already
did, except the recording coverage report and two small list endpoints the editors need.

## 1. Fixed: on screen but failing

| What | Cause | Fix | Files |
|---|---|---|---|
| A mentor opening a chapter got a page that never loaded | The page reads the course tree, which was admin only, and the failure had no catch | Mentors may now **read** the tree (`GET /api/super/catalogue`). The page shows an error and a retry if a load fails. Mentors see only the assignment card; topics, the test and chapter rules stay with the office | `SecurityConfig.java`, `ChapterDetail.jsx` |
| A mentor's module picker in Sessions to publish came up empty | Same admin-only read | Same rule | `SecurityConfig.java` |
| An admin could not see chapter test questions or use Draft five with AI | Both endpoints were super admin only, while the rest of chapter editing is admin | Opened to admin | `SecurityConfig.java` |
| A mentor saw "Can people actually join?" and got an error on Check | The join check is admin only | The card shows for the office only | `MentorSlots.jsx` |
| Mentors had no way to reach the chapter page at all, though it was built for them to set the assignment | No link anywhere outside the super admin menu | A Chapter assignment button on every chapter in the learner record | `LearnerRecord.jsx` |
| "See their learners" on My team | Worked only because the row behind it was clickable | Wired directly | `MentorTeam.jsx` |
| Four pages crashed to a blank screen on a failed load | They passed the Error object to `LoadError`, which rendered it as a child | `LoadError` renders the message | `Ui.jsx` (affects LiveBoard, ProjectReview, ProjectWorkspace, ProjectBuilder) |
| Admin command palette offered "Projects" at `/super/projects` | That route is super admin only | Removed from the admin palette | `CommandPalette.jsx` |
| Rubric writes were open to mentors | `rubrics/**` covered every method | Mentors keep read; writes are admin and super admin | `SecurityConfig.java` |
| The recording queue listed premium one to ones | The queue never filtered by kind, against its own comment | One to ones are left out of the queue and the coverage report | `RecordingService.java` |

## 3. Built new

- **Recording coverage** at `/admin/coverage`: sessions held against recorded, per mentor, over 1, 4 or 12 weeks, and the list still missing. `GET /api/admin/recordings/coverage?days=`.

## 4. Removed

- **Top 10 learner guidance** toggle. Nothing read it. The seeder now deletes it from an existing database on start.
- **Deleting a learner.** `DELETE /api/super/learners/{id}` used to delete the user, learner, form and progress, and leave tasks, projects, bookings and attendance pointing at nobody. It is replaced by deactivate, which keeps everything.
- Unused endpoints: `GET/POST /api/learner/projects` (the old free-form project, replaced by the project workspace), `GET /api/super/modules`, `GET /api/super/catalogue/setup`.

## 5. Hardening

- The server **refuses to start** with a development JWT secret (the `application.yml` or `docker-compose.yml` default) once `LMS_BASE_URL` is not localhost. Locally nothing changes.
- `.env.example` lists every switch the backend reads, with what each one does.
- `tools/check-roles.py` (new): every page's calls against what each role may call. On Version 1 it reports the five permission bugs above; on this build it reports zero.

## After you pull this

1. `mvn clean package` in `backend/`.
2. Sign in as a mentor, open a learner, Learning tab, open a chapter, press Chapter assignment. You should see the assignment card only.
3. Sign in as an admin and open a chapter. The test questions list should load.
4. Set `JWT_SECRET` before deploying anywhere that is not localhost, or the API will not start.
