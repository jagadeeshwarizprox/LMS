# Version 4, 10 October 2026: Docker ready

| Problem | Fix |
|---|---|
| nginx did not forward `/api/`, so the app broke after login under Docker | `/api/` is proxied to the API (path unchanged, forwarded-for headers set, 30 MB upload limit). Upstream and DNS are settings: `API_UPSTREAM`, `NGINX_RESOLVER` |
| Compose published web port 8081 to container port 80, but nginx listened on 8080 | Mapped `8081:8080` (`WEB_PORT` to change it) |
| Mongo had no password and was published on 27017 | Root user and password from `.env`; no published port |
| API was published directly on 8080 | Internal only; the browser goes through nginx |
| Weak defaults could start a live server | Compose refuses to start without `JWT_SECRET`, `MONGO_PASSWORD`, `BOOTSTRAP_EMAIL`, `BOOTSTRAP_PASSWORD` |
| No health checks on API or web | Both have one; web waits for a healthy API, API waits for a healthy Mongo |
| Containers stayed down after a crash or reboot | `restart: unless-stopped` |
| Mail, AI, video and import settings could not be set under Docker | All passed through from `.env` |
| Four uploaded test documents shipped inside the zip | Removed; `backend/.dockerignore` added |

New: `DEPLOY.md`, a one-page go-live checklist with backups.

Tested here: `docker compose config` (valid; refuses to start without the required values) and
the real nginx config run against the built frontend: pages, app routes, `/api/` forwarding,
caching headers and the upload limit all behave. Not tested here: pulling images and a full
`docker compose up`, because Docker Hub and Maven Central are not reachable from the build machine.
