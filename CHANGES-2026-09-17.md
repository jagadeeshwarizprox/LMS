# Changes, 17 September 2026

Fixes for `LMS_review-2.docx`, which carries three new faults, the four items from
review 1 that were still marked unsolved, three from the admin side and five from the
mentor and learner side.

Verified with `tools/offline-compile/verify.sh` (188 sources, 216 classes) and
`vite build`. The structural checkers pass apart from the two that already failed on the
previous build: the `FormFieldSeeder` startup-write note, and a template-string false
positive in `TaskThread.jsx`.

---

## Migrations

None. One behaviour change needs stating instead.

`published` is new on `CourseModule` and `Chapter` and defaults to **true**, so every
module and chapter already in the catalogue stays exactly as visible as it is today.
Only content created from now on starts as a draft. If the existing catalogue should be
audited and the unfinished parts pulled back, that is a decision and a one-off pass, not
something this build does on its own.

---

## The faults behind the list

Most of what was reported came from a handful of causes.

### A link typed into a session form was thrown away

`POST /api/mentor/slots` bound its request body straight onto `Slot`. `Slot` has no join
link field on it and never has. So the mentor filled in the Zoom link, Jackson dropped
it, the slot was saved with no room, and the learner who booked it reached the join
window and was told no meeting link was set. Nothing anywhere logged the loss.

This is the whole of "if we book the onboarding call, the zoom link for that call is not
showing in the learners LMS". Releasing now goes through `ScheduleService.createOne`,
the same path the week board already used, which turns a link into a room pinned to that
session and falls back to the mentor's standing room when the box is empty. The dead
`MentorService.releaseSlot` is gone, with a comment in its place saying where releasing
went.

The per-session link box is back on the release form. It had been removed and replaced
with a note saying there was no per-session link, which made a guest's Zoom impossible to
use at all. The form also warns when the mentor has neither a standing room nor a link on
the session, which is the exact state that produces the failure above.

### A disabled button that would not say why

`Dialog` disabled its confirm button whenever any required field was blank, silently. A
question drafted by the model has no explanation, so the Why box was empty and showing a
placeholder that read as a finished sentence: the box looked filled, and Save did
nothing with nothing said.

The button stays pressable now. Pressing it names the fields still blocking the save and
marks them red. The Why placeholder is a question rather than a sentence, and what used
to be in it is a hint underneath.

### A button for a menu that is not there

`.drawer-toggle` opens the off-canvas menu. The off-canvas menu only exists below 900px.
The button had no rule hiding it above that, so on a laptop it sat beside the breadcrumb
doing nothing at all. That is "this side bar is not working", reported twice, and most
likely "two sidebars not needed" as well. It is hidden wherever the sidebar is already on
screen.

### A pencil that was decoration

The pencil on the "in draft" tile is the `Stat` component's corner icon. Nothing was
wired to it and people pressed it for a week. `Stat` now takes an `onClick` and renders
as a real button when given one; on this board it filters the week to drafts.

### Nothing below course level could be held back

Only `Bundle` carried a publish flag. A module was on the roadmap of every learner whose
course contained it from the moment it was named, and the only way to hide unfinished
material was not to write it yet. That is review 1's "the draft modules from super admin,
the learners are also able to see that one".

`published` added to `CourseModule` and `Chapter`. Enforced in four places, not one:
`roadmap` skips drafts, `canOpenChapter` refuses them so a kept link does not work
either, `chapter()` goes through that same guard, and `LearnerProgressService` leaves
them out of the totals, because a percentage measured against invisible content never
reaches 100.

Releasing a module with no released chapter under it is refused, and so is releasing a
chapter with no topics. An empty card on a roadmap is worse than no card.

## Everything else, by where it was reported

### Review 2, new

| Reported | What it was |
|---|---|
| Save the question does nothing after editing | Empty `explanation` on old and drafted questions, blocking silently. See above. |
| That side bar button is not working | Dead `.drawer-toggle` on desktop. See above. |
| 1 in draft, edit button not working | Decorative `Stat` icon. It filters the board now. |
| Cannot edit an event once created | The board could add and reassign and nothing else. `PUT /api/week/sessions/{id}` added, with an edit drawer. |
| Random text accepted instead of a link | `Validate.link` on create and update, plus a client-side check that does not wait for the server. |

Session editing came with the rest of what was missing: `DELETE /api/week/sessions/{id}`
deletes a session nobody booked and cancels one with people on it, keeping it on their
week with a reason rather than making it vanish. Seats cannot be reduced below the number
already booked. A mentor may change what they host; reassigning and releasing stay with
the office, enforced server-side rather than by hiding a button.

### Review 1, the four left open

- Sidebar button, and the second sidebar: fixed above.
- Draft modules visible to learners: fixed above.

### Admin side

| Reported | Change |
|---|---|
| "That batch code already exists" when adding a student | `Register` filtered closed batches out of its dropdown, so a late joiner who belonged in a running cohort left the admin with nowhere to put them, and they went and recreated the batch. Closed batches are listed and labelled now. The conflict message also says to use Register and pick the batch rather than stopping at "already exists". |
| A batch can be created with no name | Name required, server and form. A register full of rows called B57 is unreadable. |
| Kind is missing Interactive and Debate | Both added, and threaded through every label map that had drifted: the board, the schedules page, both mentor maps, the learner map, `ScheduleService`, `ThisWeekService` and `RecordingService`. Both follow the `live_sessions` toggle in `FeatureService`. |

### Mentor and learner side

| Reported | Change |
|---|---|
| Form should redirect to the prerequisite video | It saved section by section and never navigated, so finishing left you sitting on a completed form. It goes to `/learn`, where that gate lives. |
| Resume needs pdf/doc upload, not just a link | `fileId` on `ResumeVersion`. Either a file or a link, one of the two required, links validated. The `RESUME` file purpose was already in the download guard. |
| Onboarding recording: link not taken, no PDF upload | The form posted `externalId`, a field `PublishInput` has never had. It was dropped, the server saw neither link nor file, refused, and the form blamed the link. Worse, the box was labelled "Recording link" while its note asked for a YouTube id, so whichever you pasted was the wrong one. It posts `videoLink` and `fileId` now, with an upload beside it. |
| Slot released 5 minutes before is not visible | No lead-time rule exists server-side, so this was the page: it fetched once on mount and never again, and releasing a day ahead only looked like it worked because the learner opened the page fresh the next day. It polls every 30s while the tab is visible and refetches on focus. |
| Zoom link not showing for a booked onboarding call | The dropped link. See above. |
