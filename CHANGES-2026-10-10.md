# Version 3, 10 October 2026: every save checked

Every save, submit, edit and delete across all four roles was audited on both sides,
frontend body against what the backend actually stores. About 70 defects were fixed,
then an independent review of the changes found 7 regressions, which are also fixed.

## 1. Saves that wiped or reset stored data

| Where | Before | Now |
|---|---|---|
| People and Mentors, edit | Wiped phone, WhatsApp, last sign in; lifted a suspension | Only the fields sent change (`SuperAdminService.updateStaff`); WhatsApp is prefilled |
| Modules, edit | Released a draft, reset position, revived archived | Keeps published, active and position |
| Courses, edit | Reset access and colour to defaults | Unsent fields are left alone |
| Paste an outline | Empty chapters went live | Pasted chapters start as drafts |
| Move learner to another batch | Re-locked a mid-course learner | Only resets gates for someone still onboarding |
| Resend login | Overwrote a password the learner had set | Refused once they set their own; use Reset password |
| Enrol an existing email | Moved them to a new mentor | Mentor assigned only on create or premium upgrade |
| Change one session's link | Changed every session of that mentor | The session gets its own pinned room |
| Repeating schedule save | Could replace someone else's whole schedule | Ownership checked, only sent fields merge |
| Task re-review | Wiped the score | Score kept when none is sent |
| Project stage re-review | Overwrote the last attempt | Each review appended; sending back re-locks later stages |
| Teach back retake | Could null a graded score | Graded score kept; new answer stored as pending |
| Rewatching a video | Progress went backwards | Highest progress kept, completed stays completed |
| Chapter notes | Empty box could save over the note | No editing or saving until the note loads; per-chapter |
| Moved or deleted sessions | Came back the next night | Remembered and skipped by the generator |
| Watched import folder | Re-read old files, undid admin changes | Files move to `processed/`; hand moves are respected |

## 2. Permission holes closed

- Learners: marking watched needs real playback (90% of the video, counted from played time, not scrubbing); tests, teach back, tasks and doubts need the chapter to be open; an approved task can't be reopened by resubmitting; private one-to-ones can't be booked or joined by id; induction can't be cleared early; the information form checks required fields on the server.
- Mentors: cancel, move, attendance and notes only on sessions they run or cover; project reviews, messages, tasks and resume sign-off only for learners they can see.
- Admins: can't switch off, reset, reassign or suspend another admin or the super admin; nobody can suspend a super admin; a switched-off account is signed out at once.
- Mentor assignment and "move learners" accept only active mentors, write history, and move the departing mentor's batches.

## 3. Saves that silently did not work

- Set a task for a whole batch (sent the batch code, now the id).
- Show this chapter in the roadmap (new `/chapters/{id}/active`).
- Logging a call now closes the pending call.
- Course chosen at enrolment is used by id; import matches names exactly; an unknown batch code is reported, not invented; preview "Already here" counts correctly.
- Mentor room no longer errors once a mentor has used a one-off link (existing data repaired by `LegacyRoomMigration` on start).
- Quiz drafter page loads its own modules.
- Enrolment errors keep the form and show the reason.

## 4. Duplicates and silent failures

- Busy guards on quiz, teach back, task, mock request, check in, log call, publish, release, resume, review and comment.
- Bulk approve reports real approved and failed counts.
- One app-wide error toast for failed requests (deduplicated, skips background 401s).
- Loading errors show a retry on Module, Course, Activity log, Settings, Form, FAQs and Features.
- My desk review box keeps focus while typing.
- Removing an uploaded file removes it from what gets submitted.

## 5. Switches and settings that did nothing

- Removed 10 app settings no code read (cleaned from existing databases on start). Resetting "Require onboarding" applies at once.
- Removed the unenforced course access card and the "No price set" readiness item.
- Removed the two teach back switches and "Mentor review required"; switched-off rubrics are no longer offered.
- AI draft questions no longer count as a written test; publishing a draft applies the same checks as a hand-written question.
- Deleting a chapter or module removes its files and switches off its videos.

## Decisions taken for you

- A learner with a recorded track or batch move is not upgraded by a sheet import (manual enrolment is not blocked).
- Settings and switches that nothing read were removed, not wired in.
- A topic with no video at all can still be marked done, so document-only topics never lock a chapter.
