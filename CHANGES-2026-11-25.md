Every point marked Not Implemented in the review document, traced from the screen to
the code before anything was changed. Nothing marked implemented or working was
touched: Open now, upload limits, Drive and upload sharing, the batch induction flow,
module delete, batches and learners views are as they were.

## Super admin: modules and chapters

**1. Move topics between chapters.** The server already took a topic with a new
`chapterId`; the form had no way to send one. The topic Edit form now has a
**Chapter** dropdown listing every chapter of every module. Choosing another one moves
the topic, with its video, files and watch history, to the end of that chapter, and
the page follows it there. Server side the moved topic now takes the last position in
its new chapter (it kept its old position before, so two topics could share one), and
a move across modules carries the video document's module with it.

**3 and 9. Rename a module or a chapter.** Module rename existed on the module page
(`/super/modules/:id`) but that page could only be reached from a course or straight
after creating the module. The Modules list now has **Open module** on every row.
Chapter rename existed nowhere: the chapter page has **Edit** (title and one line) in
its header, and the module page has **Rename** on every chapter row.

**4. Add a chapter from the chapter page.** **Add a chapter** in the chapter page
header creates the next chapter in the same module and opens it.

**5. Back to chapters.** "Back to modules" went to the whole list. It is **Back to
module** now, and lands on the module's own page: its chapter list, add, rename,
delete and release.

**6. No delete on topic files.** Remove was there, pushed off the right edge of the
panel: the actions cell was `nowrap` and the topic column is no wider than a drawer.
The chapter workspace now lays the file list out the way the drawer already does,
actions on their own line under the file name, so all five controls show. Remove also
asks before it acts, and says that the uploaded file itself is kept.

**8. A notebook accepted under Notes.** Nothing checked that the button pressed
matched the file chosen, and the drop zone filed everything as Notes. The rule is now
in both places, from one table:

| Kind | Takes |
|---|---|
| Notes | pdf, doc, docx, odt, rtf, txt, md, html, images |
| Code | ipynb, py, r, rmd, sql, js, ts, java, c, cpp, cs, go, rb, php, sh, css, scala, m, jl, zip, tar, gz, tgz, 7z, rar |
| Dataset | csv, tsv, xls, xlsx, ods, json, xml, yaml, yml, parquet, pbix, pbit, twb, twbx, qvf |
| Slides | ppt, pptx, odp |

The picker only offers that kind's types once a button is pressed; a dropped file is
filed under the kind its extension says; a mismatch is refused by name
("x.ipynb is a code file; add it under Code, not Notes"). The server applies the same
table (`FileService.kindForFile`), so it holds for any client. A row filed under the
wrong kind before this existed is corrected the next time it is saved rather than
refused.

## Mentor side

**3. Repeating sessions: no edit.** The page had Pause and Resume; the server took an
edit all along. **Edit** opens the same form, prefilled. Found while doing it: the
slot generator is idempotent on the old key, so changing the time would have left the
next two weeks standing at the old time and added a second set at the new one. On an
edit the server now brings the already generated slots in line: future slots nobody
has booked are moved (dropped and regenerated at the new time) or rewritten in place
(length, seats, kind, audience, topic, speaker); a slot somebody has booked, or one
already held or cancelled, is left exactly where it was. The toast says what happened:
"Saved. 2 upcoming sessions moved to the new time. 1 already booked, left as it was."

**4. Mark as held did not complete the learner's onboarding.** The desk showed
"0 of 1 booked": the learner had never booked that slot, so held had nobody to mark.
The cause was point 7, a mentor-created session is a draft and learners cannot see or
book a draft; the call ran anyway. Three changes:

- The desk row names who booked ("1 of 1 booked: Priya S"), for sessions of up to
  eight bookings.
- Mark as held is a dialog, on the desk and on Your slots, listing everyone booked by
  name with a present tick, and under it **Who attended?** (or "Anyone else who
  attended without booking"): the premium learners the host can see, the ones still
  waiting for their onboarding call first. Each one ticked gets the booking they would
  have made, marked attended, and the same attendance row as a booked learner, so the
  gate clears through the one path that clears it. The server only accepts learners
  the host can see (their own, or those they cover); an admin may name any.
- Point 7 removes the cause.

The batch induction flow is untouched: batch learners never book, and Mark induction
done on the Batches page still clears the whole batch, as confirmed.

**7. Created sessions showed as Draft.** A mentor's one-off session is now live as it
is saved, the way their repeating sessions always were. Admins keep the "release now"
checkbox and the week-level release. The form says so instead of the draft note.

## Admin portal

**4. Import from sheet: the learner list was not shown.** The preview showed four
counts; names appeared nowhere until after the import, and then only email and status.
Both the preview and the result now list every row read from the sheet: name, email,
track, batch, course, and what will happen (Will be created, Will move to premium,
Already here, or the reason it is skipped) or what did.

**5 and 6. Change the assigned course; batch to premium and back.** Both existed on
the learner's record under the **Move** tab (change course, move batch, change track,
hold), with progress, mentor and records kept by the movement service. Nobody found
the tab. Every All Learners row now has **Change course** and **Move to premium** /
**Move to batch**, which open that tab directly (`?tab=move`). No new logic.

**2. Recording coverage, "Last 3 months".** The third option is the 90-day window.
The null could not be pinned from the code alone; every null path in the window read
is now closed (a slot with no start, no id or no kind is skipped; a mentor with no name
reads as Unknown; the pending list is matched by slot id, not scanned). If it still
fails, the API log line for that click names the exact cause.

## API

- `POST /api/week/schedules` now returns `{ id, schedule, note }` rather than the bare
  schedule. Only the Repeating sessions page calls it.
- `POST /api/mentor/slots/{id}/held` takes `attendedLearnerIds` beside
  `absentLearnerIds`.
- New `GET /api/mentor/slots/{id}/held-options`: who booked, and who may be recorded.
- `POST /api/week/sessions` from a mentor is published; the office's checkbox stands.
- Import preview and result carry `learners` (one row per sheet row) beside `rows`.
