# Changes, 10 September 2026

Fixes for the issues raised in `LMS.docx`, `mentor_and_student_LMS_report.docx` and
`Admin_Portal_Errors.docx`, plus three faults found while working through them that
nobody had reported.

Verified with `tools/offline-compile/verify.sh` (188 sources) and `vite build`. The
structural checkers pass apart from two items that already fail on the previous build:
the `FormFieldSeeder` startup-write note, and a template-string false positive in
`TaskThread.jsx`.

---

## Migrations

Three run once on startup, each behind its own flag in `app_settings`, each safe to run
against a database written under the old rules.

- `MentorIdBackfill` — gives every batch learner their batch's mentor.
- `PublishFlagBackfill` — marks existing courses published, and publishes slots that
  were already released.
- The feature seeder now corrects labels on databases that already exist, instead of
  only ever adding what was missing.

Nothing is deleted and no learner's chosen password, progress or toggle state is touched.

## The three root causes

Most of the reported list came from three faults rather than thirty.

### Learners were never given a mentor

`ProvisioningService.provision()` set the learner's batch and not their mentor. Nothing
downstream could tell that apart from a learner who genuinely had nobody, so the mentor's
roster was empty, their learner count read zero, the analytics mentor rollup folded
everybody into one Unassigned row, task queues were empty and one-to-one booking failed
its own mentor check.

One line, plus a backfill for the learners already in that state.

*Closes 3, 4, 14, 35a, and part of 34.*

### The publish flag was decorative

`Bundle.published` was written by the publish button, displayed on the course list, and
read by nothing. Learners were served half-written chapters, topics with no video and
quiz questions the model had drafted and nobody had reviewed.

Every learner-facing path now goes through one `publishedCourseFor()` check.

*Closes 29.*

### Routes existed that the frontend never called

`DELETE /super/catalogue/bundles/{id}` and `DELETE /super/catalogue/questions/{id}` were
both implemented and neither was ever called. A course created with a typo kept it for
ever and a saved question could only be corrected in the database.

*Closes 23, 26.*

## Found while working, not reported

**Released slots were invisible to learners.** `releaseSlot()` set `open` and never
`published`, and the learner's slot query filters on `published`. Every slot any mentor
has ever released was open, in scope, allowed by the feature toggles, and unreachable,
while the toast said "Slot released to learners." This was the real cause of 34; the
missing mentorId was only the second half of it.

**`saveBundle` overwrote whole documents.** Nothing had ever called it with an id, so
nobody had found out. The Edit button added in this pass would have blanked price,
access, cover image and the publish flag on first use. It merges now.

**The sidebar was styled twice.** `console.css` re-declared `.sidebar`, `.nav-link` and
`.nav-pill`, all of which `theme.css` already owned, and loads second. Changing the active
state in the obvious place did nothing, which is most of why it stayed broken.

### On 20 and 28

There was always a save button. `.dlg` had no height limit and no overflow, so a dialog
with seven fields in it grew past the bottom of the window and took its own footer with
it. The button could not be reached and could not be scrolled to, so pressing return was
the only way to finish. The fields scroll now and the footer is pinned.

## Behaviour worth knowing about before deploying

- **Learners on an unpublished course will see an empty roadmap.** The backfill marks
  every existing course with modules as published, so this should affect nobody on
  upgrade. A course with no modules stays unpublished, which is the case the gate exists
  for.
- **A question can no longer be saved without an explanation.** Existing questions are
  untouched; this applies on the next save.
- **Batch learners cannot be enrolled without a batch from the register.** The sheet
  import still places automatically, because nobody is watching it.
- **Staff sessions are no longer exclusive.** Turn on `access.singleSession.staff` in
  Settings to restore the old behaviour. Learners are unchanged.
- **Test scores are now marks earned over marks available.** Every question defaults to
  one mark, so no existing test's outcome moves.
